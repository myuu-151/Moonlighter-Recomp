Dungeon oracle report

Every dungeon floor below was generated by the real game and recorded by the oracle plugin. The C++ port replays each recorded step from the game's own random state and must land on exactly the same result. This page shows what was checked and what those floors look like, so you can look over a few by eye.

      Game bugs the port keeps on purpose

      Timed chests never spawn

      Their count is Random.Range(0, 1); the maximum is exclusive, so it is always 0. The draw still happens.

      The room asset is stale

      The serialized DungeonRoomDatabase has weights already penalised and older zones. Each floor, LoadFromJSON overwrites it from the rooms text: through a boxed copy, but the room objects are shared. That is also what resets the ×0.001 weights.

      Lights only on a floor's first room

      AddLightShadow aliases the dungeon's sprite list and the next room's SetLights clears it, so only the start room gets a random light and shadow.

      UnloadBundlesExcept is inverted

      It unloads only the culture it should keep. Other dungeons' sprite lists stay emptied all session, so corrupted rooms never get lights.

      Room names aren't unique

      The database holds two different Golem_Enemies_13 designs; GetRoomByName always returns the first. The port tracks rooms by database index instead.

      Boss miner eats the miner list

      BossRoomMiner.Init removes from the generator's live miner list while searching for a spot. Copying the list changes every floor 3.

      Corrupted room lists shifted

      Forest's corrupted rooms are filed under Golem, Desert's under Forest, Tesla's under Desert; Tesla gets a mix.

      Grid one row too big

      LoadGridFromInfo allocates 20 + 20×11 tiles; rooms that skip it keep the prefab's 20×11.

      Unstable sort matters

      Chest rooms are sorted with Mono's introsort; a stable sort changes 6 of 3,000 layouts.

      Wasted pick before the miniboss

      On floors 1–2 the next-floor room first draws a normal room (penalising its weight) and then is replaced by the miniboss room.

      Boss chests fill twice

      Post-boss chests roll random contents in Awake; PostBossSpawnEnemyController then empties them and rolls again with the boss drop bonus (keeping any amulet). Both rolls draw.

      Item list sort isn't a sort

      Chest item weights are sorted with (int)(y.weight - x.weight), which truncates small differences to 0 and is non-transitive. The order is dumped from the game, not rebuilt.

      Wanderer shuffle by broken comparer

      The DLC picks the intermediate room's host by sorting with Random.Range(0, 1000) as the comparison. The draw count depends on Mono's introsort, so the port runs the same introsort.

      Shrine log crash

      If no Desert room qualifies for the hard-enemies shrine, the log line reads the null room's name and the coroutine dies there.
