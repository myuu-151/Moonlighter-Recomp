Moonlighter → GameCube on Octave-libogc

Moonlighter GameCube port

A native C++ reimplementation of Moonlighter, translated from the decompiled game code and checked against the real game automatically, so correctness doesn't depend on watching it run. This page collects what's been measured and built so far.

Fitting it on a GameCube

All 9,413 unique textures were decoded and measured. Only 23% of their area holds anything; the rest is empty atlas and frame padding. Repacking at full resolution is what makes the game fit, not downscaling.

Downscaling verdict

The art is true 1:1 pixel art: none of it is stored pre-upscaled, and halving it costs a median 30/255 error, enough to erase outlines on ~32 px characters. The soft light, shadow and glow layers are the exception (median error 3/255): at quarter resolution they shrink from 19 MB to about 0.4 MB.

How correctness is checked

1 · Record

Oracle in the real game

A BepInEx plugin logs Unity's random state and every decision as the game generates floors: picks, grids, spawns, chests.

2 · Replay

C++ port from the same state

Each step of the port starts from the game's recorded random state, so one mistake can't cascade into later steps.

3 · Compare

Bit-for-bit

Same result and same number of random draws, or the test names the first difference. No one has to watch it.

Things exactness depends on (found so far)

  • No fused multiply-add. GCC on the GameCube CPU fuses a*b+c unless built with -ffp-contract=off, and the RNG's float range drifts.
  • Unity's float range is reversed: t*min + (1-t)*max.
  • Mono's sort, exactly. Introsort is unstable, and its depth limit comes from the list's capacity, so List<T> tracks .NET's growth rule.
  • Reference semantics. The game mutates shared objects (miner lists, room weights, sprite lists); the port keeps C# reference behaviour instead of copying.
  • Hidden draws in prefab scripts. Chests shuffle 27 times on spawn, Tangles draw twice, decorations up to ~580 times per room; the oracle measures each.

What's next

  • Render a generated floor from extracted room art, then diff it against the oracle's object snapshot (positions, sprites, sorting) instead of eyeballing it.
